# Retrieval baseline refresh: 2026-10-24

The push and pull-request CI runs for `36562d8` completed retrieval evaluation but all three
dataset gates exited with code 2 because their committed index fingerprints were stale.
Tests and the fixture gate passed. This refresh updates the three real-dataset baselines using
completed push-run reports; it changes no retrieval code, gate checks, or metric tolerances.

## Cause and verification

Commit `48b212a` added `SourceQuery.metadata`. `hash_dataset()` serializes the query contract,
so the metadata became part of the corpus hash and, transitively, the index fingerprint.
The fixture baseline was refreshed in `740d3ea`; the three real-dataset baselines still
referenced runs from before that schema change. Cold index builds in the October runs surfaced
the discrepancy.

For each checksum-pinned dataset, an independent local calculation reproduced the old
baseline fingerprint by excluding query metadata and reproduced the observed CI fingerprint
by including it. The calculation used the same BM25 artifact bytes, embedding model,
normalization, vector dimension, and HNSW parameters. Metadata provenance remains part of
the fingerprint; the strict comparability check is preserved.

Before refreshing, all 48 metric comparisons passed the existing 0.01 absolute-drop
tolerances in both CI runs. SciFact and FiQA metrics were identical to their old baselines.
NFCorpus had small changes, detailed below; its largest decrease was 0.00297619 MRR@10.
